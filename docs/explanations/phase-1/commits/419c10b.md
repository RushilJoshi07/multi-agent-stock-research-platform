# 419c10b — Number checker: unusual stored values are rejected with a correct message
2026-11-11 · 3 files changed, 98 insertions(+), 2 deletions(-)
Hole 5 from the review: validate_claims now checks the stored value's type before comparing.
A result that isn't a mapping, a null, a bool, any non-number and inf/nan each get their own
error instead of a crash. Non-obvious: bool is a subclass of int, so True has to be excluded
explicitly or it counts as 1.0. Numeric strings ("1.0") are rejected too; stored results are
JSON numbers, and a string there means something upstream went wrong.
